# 상담 쉼 카페

PRD 기반의 홍보 및 예약 웹앱. Vinext/React와 Cloudflare D1을 사용한다.

## Vercel 배포

`vercel.json`이 Next.js 프레임워크와 `node scripts/build-vercel.mjs` 빌드 명령, `.next` 출력 경로를 지정한다. 기존 Sites 빌드는 `dist/`에 Worker를 생성하므로 Vercel의 Next.js 출력 형식과 호환되지 않는다.

로컬 검증은 `pnpm build:vercel`, 실행은 `pnpm start:vercel`을 사용한다. Sites 전용 Cloudflare 모듈은 Next.js 빌드에서 빈 바인딩으로 교체한다. Vercel에서는 예약 DB 및 Sites 로그인 연동이 제공되지 않으므로 예약 API는 503 준비 중 응답을 반환하며 사용자 입력 헤더를 인증으로 사용하지 않는다. 홍보 화면과 준비 중 팝업은 정상 제공된다. 실제 예약 운영에는 Vercel용 DB와 인증 연동이 별도로 필요하다.

GitHub `main` 푸시 후 Vercel 자동 배포 결과를 확인한다. 예전 배포 화면의 Redeploy는 예전 커밋을 다시 배포할 수 있으므로 최신 커밋의 배포를 확인한다.

## 현재 구현

- 반응형 공간·신메뉴 소개, 프로그램 소개
- 로그인 사용자별 예약 신청·조회·취소
- 운영자 이메일 허용 목록에 따른 접근 제어
- 운영 가능 시간 등록, 예약 승인·거절
- 단일 원자적 SQL로 같은 시간 및 겹치는 시간의 중복 승인 방지
- 승인 전 결제 요청 차단, 승인 후 24시간 기한 검증
- 만료 시 접근 시점에 미결제 예약 정리 및 시간 해제
- 한국 시간 기준 이용일 2일 전까지 환불 요청 접수
- 결제 실패·재시도·중복 알림 정책 함수 및 테스트

## 개발

Node.js 24 이상, pnpm을 사용한다. `pnpm install`, `pnpm db:generate`, `pnpm build` 순서로 실행한다. 로컬 D1에는 생성된 drizzle SQL을 Wrangler로 적용한 후 `pnpm dev`로 시작한다. Sites 스킬의 로컬 D1 절차를 따른다. 테스트: `node --test tests/*.test.mjs`. 타입 확인: `pnpm exec tsc --noEmit`.

## 운영 설정과 남은 작업

- 사이트는 비공개 개발 확인용이다. 예약 본인 확인에는 Sites의 ChatGPT 로그인을 사용한다. 일반 고객용 전화 본인 확인은 미구현이다.
- `ADMIN_EMAILS`에 실제 운영자 로그인 이메일을 등록해야 관리자 기능을 쓸 수 있다. 기본값은 모든 관리자 접근 거부다.
- 실제 운영시간이 제공되지 않았으므로 예약 시간은 자동으로 만들지 않는다. 관리자가 등록한다.
- **결제대행사 미선정: 실제 결제·결제 성공 콜백·환불 송금은 미구현이다.** 결제 요청은 승인/기한을 검증한 후 503 안내를 반환한다. 테스트 정책 함수가 실결제 연동을 대신하지 않는다.
- 실제 연동 시 서버 승인 API, 서명 검증 웹훅, 결제 ID 유일성 및 이벤트 원장, 원자적 확정, 기한 이후 입금의 환불 처리를 구현해야 한다. 결제 이벤트 테이블은 이 후속 작업을 위한 스키마다.
- 만료는 요청 시 처리한다. 운영용으로 정기 정리 작업과 안내 발송을 추가해야 한다.
- 안내 문자·이메일 자동 발송은 미구현이다. 승인 상태는 내 예약에서 조회한다.
- 환불은 현재 접수 상태까지만 처리한다. 전액 환불을 초안으로 두었으며 실제 환불 금액·처리 기간과 최종 정책은 출시 전 확인한다.
- 승인 시점이 이용 시작 24시간 이내인 경우의 결제 마감과 이용 시작 전 마감 규칙은 추가 결정이 필요하다.
- 매장 사진·주소·운영시간·메뉴 가격·진행자 소개·개인정보 보관/삭제 정책을 제공받아야 한다. 현재 원격 사진은 분위기 참고용이며 실제 매장·메뉴 사진으로 교체한다.

실제 고객 정보 수집과 결제 운영은 위 항목을 완료한 뒤 시작한다.
